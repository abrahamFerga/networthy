## merge-gate.mjs counts superseded check runs as failures

Found 2026-08-03 on #146. `statusCheckRollup` returns **every** run for a head SHA, not the latest
per name. After a gate failure is fixed, the SHA carries both:

```
PR gates  FAILURE  13:19:53
PR gates  SUCCESS  13:25:07   <- latest; what branch protection actually uses
```

`merge-gate.mjs:91` filters for any entry in FAILURE/ERROR/CANCELLED/TIMED_OUT, so it reports
`checks_green` red while GitHub reports the PR green. Because `agent-gates.yml` deliberately re-runs
on `edited` and `labeled`, superseded failures are the NORMAL case — which means any PR that fixes a
gate failure can never satisfy `checks_green` again. Deduplicate by check name, keeping the newest
`startedAt`, before deciding `broken`.

Do not patch this locally: `.github/**` is spine, and editing a gate so your own PR passes is the
specification-gaming move the loop exists to prevent. It belongs in the plenipo-agents asset.
